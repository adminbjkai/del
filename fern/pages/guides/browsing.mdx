Once a scan has run, everything DEL found is browsable from the sidebar. This page
opens with the **View Apps** launchpad and covers the two inventory views —
**Applications** and **Resources** — plus the table
controls and badges you'll see throughout. The sidebar also has a **Docs** link
(opens this documentation site in a new tab; docs are open — no separate basic
auth. The app UI still requires your DEL login).

## The View Apps launchpad

**View Apps** is the clean, homelab-style gallery for opening web applications.
It is intentionally stricter than the inventory table: a card appears only when
the application and its enabled Nginx domain are present in the latest completed
scan **and** a live HTTPS check succeeds. DEL verifies DNS, TLS, the Nginx route,
and that an upstream answers. HTTP responses below 500 count as online (including
login challenges and apps whose root path returns 404); connection failures and
5xx responses stay hidden.

Health results are cached for five minutes and the page renders from that cache
immediately, re-checking stale domains in the background — so the gallery stays
fast and the status you see may be up to a few minutes old. **Refresh health**
(`?refresh=1`) forces a fresh check and waits for it.

Each card shows the site's favicon when available, domain, live HTTP status,
response time, and a link back to its DEL inventory detail.

<Callout intent="info">
  **Icons are fetched by DEL, not by your browser.** Cards load them from DEL's own
  `/app-icon/{domain}` route, which only accepts hostnames that are enabled Nginx
  sites in the latest scan. If an app has no reachable icon — or sits behind HTTP
  basic auth and answers `401` — DEL absorbs that and the card falls back to the
  app's initial letter. Previously the browser requested those favicons directly,
  so every basic-auth-protected app popped a credential dialog on top of the gallery
  you were already logged into.
</Callout>

Use the toolbar to:

- search names, domains, and categories;
- filter by category or favorites;
- sort by name, domain, response time, category, or your saved order;
- switch between grid and list views;
- customize card width and spacing;
- star, recategorize, hide, and drag cards into a personal order.

<Callout intent="info">
  Gallery customization is stored only in this browser's local storage. It does
  not edit Nginx, manifests, applications, associations, removal plans, or any
  other server-side DEL state.
</Callout>

## The Applications list

**Applications** lists every application DEL correlated, one row each. The count
pill next to the heading shows the total. Click any application name to open its
[detail page](#the-application-detail-page).

<Frame caption="The Applications list, filtered to a single app. Each row shows status, kind, domains, ports, resource count, warnings, and whether the app is protected.">
  <img src="../../assets/03-apps-list.png" alt="Applications list filtered to deldemo" />
</Frame>

Columns: **Name** (with the slug beneath — click the slug to copy it), **Status**,
**Kind**, **Installed** (best available install-time signal: Docker container
`Created`, project directory age, or when DEL first discovered the app — shown in
Eastern time as compact `MM-DD-YY H:MM AM/PM`), **Domains**
(each a clickable link to the site), **Host ports**, **Resources** (count),
**Warnings** (an amber badge when non-zero), and **Protected** (a blue badge for apps
DEL will refuse to remove, such as DEL itself).

Use **Show removed too** / **Show live only** at the top of the page (or
`?show=removed` in the URL) to include apps that no longer appear in the latest
completed scan. **Export CSV** downloads the currently filtered/visible rows.

<Callout intent="info">
  By default, **Applications** only shows apps present in the **latest completed
  scan** — once an app is fully removed, it disappears from this list on its own (a
  successful live removal triggers an automatic rescan, so you don't have to remember
  to refresh it yourself). During a running rescan the UI keeps showing the previous
  completed inventory so the list does not briefly empty. Visiting a removed app's
  detail page directly shows a "not present in the latest scan" banner instead of a
  404, so its history stays reachable. Detail pages show **Installed**, **First seen
  by DEL**, and **Last seen by DEL** as real timestamps (not internal scan IDs).
</Callout>

## Glossary rail

On wide screens a **Glossary** panel sits on the right and explains the labels for
**whatever page or resource tab you’re on** (it updates with the tab). Entries cover
Status, Warnings, Protected, State/health, Dangling, Orphan classes, Shared,
Dirty/clean, and more. On phone and tablet, open it with the floating **Glossary**
button (bottom-right).

## Table controls (AG Grid)

Data tables use **AG Grid Community** (self-hosted, no CDN) with a light theme that
matches DEL. Controls are client-side only:

- **Sort** — click a column header.
- **Quick filter** — top box matches **all columns**. Press **`/`** to focus it.
- **Per-column filters** — click the floating control under a header for an
  Excel-style panel: **checkbox list of existing values** (select all / clear /
  search values) plus text operators (**contains**, **does not contain**, equals,
  starts with, ends with, …).
- **Clear all filters** — one button resets every column filter and the quick filter.
- **Pagination** — page size selector in the grid footer.
- **CSV export** — on Applications, exports the **currently filtered** rows.
- **Deep links** — `/apps?search=…` prefills the quick filter.

## The Resources view

**Resources** shows every discovered resource, split into a **tab bar** by type.
Each tab's count pill tells you how many of that type exist.

<Frame caption="The Resources view on the Volumes tab. Note the tab bar with per-type counts, the orphan badges, and the owner column.">
  <img src="../../assets/11-resources-volume.png" alt="Resources volumes tab" />
</Frame>

The columns are tailored per type — for example volumes show mountpoint, containers
using them, and an **orphan** badge when nothing is using them; nginx sites show
server names, config path, upstream ports, and an **ssl** badge. Two columns are
common to almost every type:

- **Owner app(s)** — which application(s) DEL attributes the resource to, each a link
  to that app. Resources DEL couldn't attribute to a current, confident owner show an
  `unassigned` badge (these are the [orphans](/guides/orphans)).
- **Shared** — an amber **shared** badge marks a resource associated with **more than
  one** application. Shared resources are protected: removing one app's plan will
  never silently delete something another app still depends on.

## The Application detail page

An application's detail page is where you review everything DEL believes it owns
before planning a removal. Resources are grouped into collapsible sections —
**Docker**, **systemd**, **Nginx**, **Scheduled**, **Processes**, **Files /
Storage**, and **Shared resources**.

<Frame caption="An application detail page with every section and its evidence expanded.">
  <img src="../../assets/04-app-detail.png" alt="Application detail page" />
</Frame>

For each associated resource you see:

- a **Confidence** badge (`confirmed`, `high`, `probable`, `possible`) — explained in
  [Understanding Confidence](/guides/confidence);
- a **Risk** column (`data`, `config`, or `safe`), flagging data-loss potential;
- a **Removal** column (`safe` / `blocked`) showing whether it is eligible;
- an expandable **Evidence** list — the specific facts (with weights) behind the
  association, e.g. *"[docker] compose project label = deldemo (weight 100)"*;
- an **Actions** cell with **approve**, **exclude**, and **mark shared** — see
  [approving resources](#approving-and-excluding-resources).

At the top of the page, **Plan removal** starts a
[removal plan](/guides/removing-an-application) (disabled and greyed out for
protected apps), and **Edit manifest** lets you correct DEL's correlation by hand.

Below the grouped sections, a **Removal readiness** table lists every
association for the app in one flat, sortable/filterable list — the same
Confidence/Risk/Removal columns, but every row also carries a small
**resource-type** badge (`container`, `directory`, `compose_project`,
`git_repo`, …) in front of its name. This matters because two entirely
different resources can share the same display name — e.g. a `compose_project`
named `cap4` and a plain `directory` also named `cap4` are distinct resources
DEL might both associate with the app — so the type badge, plus the file path
shown under any path-like resource, is what tells them apart at a glance
instead of the row looking like a duplicate.

### Approving and excluding resources

The **Actions** on each resource row let you override DEL's automatic correlation:

- **approve** — release a `shared` resource for removal by *this* app, or approve a
  named volume for deletion.
- **exclude** — drop a resource from this app's associations regardless of what
  correlation found.
- **mark shared** — flag a resource as shared so it is preserved rather than removed.

These are the controls you use immediately before planning, with two limits worth
knowing:

<Callout intent="warning">
  **approve does not promote a `probable` association.** The plan builder preserves
  every `probable` row unconditionally. Approve is only for shared resources and
  volumes — see [Understanding Confidence](/guides/confidence).

  **None of the three survive a scan.** Each scan deletes and re-inserts an
  application's associations, so these flags are wiped on the next rescan. Record
  lasting corrections in the app's manifest (**Edit manifest**) instead.
</Callout>

## The Jobs list

**Jobs** lists removal jobs DEL has run — both dry-runs and live runs — newest
first, capped at the most recent 200. Each row links to the app, the plan it
executed, and the job detail, and shows a **Mode** badge (grey `dry-run` or red
`LIVE`) and a **Status** badge. It's the audit trail of everything DEL has changed
on the host; older jobs remain in the database and are still reachable by URL.

## Keyboard, screen readers, and printing

The interface is usable without a mouse and legible on paper:

- A **Skip to main content** link is the first thing Tab reaches on every page.
- The **Glossary** sheet and the mobile nav drawer trap focus while open and return
  it to whatever opened them on close.
- Table headers carry `scope`, tables carry captions, and sortable columns announce
  their state with `aria-sort`; filter inputs are labelled.
- Copy buttons (for example, an app's slug) are reachable and activatable by
  keyboard, not hover-only.
- Button fills meet WCAG AA contrast.
- `prefers-reduced-motion` is honoured — animations and transitions are suppressed
  for anyone who has asked their system for that.
- Print styles drop the navigation, glossary and skip link, so printing a page or
  saving it as PDF produces the content rather than the chrome.
