Help

Applications
Status
Runtime state DEL last correlated:
  • running / active — up now
  • stopped / exited / inactive — installed but not running (or, for a manifest-only source clone, nothing to run)
  • paused / unknown — held or unclear
  • absent — only a manifest names it; none of its folders, units or containers exist on the host any more
Warnings
Weak associations (ownership enum possible, or confidence band possible — score under 60). Probable (≥60) is a strong claim. Review weak rows before planning — not an app health check.
Protected
DEL will not build a removal plan (e.g. DEL itself).
Installed
When the app first appeared on this host, in Eastern time: the earliest creation (birth) time of its own folder, service unit file, enabled nginx site file or container. Shown as “by” a date when DEL's first scan is earlier than every creation time it can read.
Last changed
The newest of: a file added or removed in its folder, its last git commit, a container recreate, or an edit to its unit or nginx site file.
Kind
Primary runtime: compose, container, systemd, …
Status by scan
On an app's Overview: one bar per completed scan (oldest left, newest outlined), coloured by the status that scan recorded. Scans record per-app status from 2026-10-03 on; an empty bar means the app was not in that scan's inventory.
How it is wired
The app's own resources (excluded rows left out) in four lanes: the domains that reach it, the ports it listens on (a stopped container's published port shows as not listening), what runs it, and where it keeps data. Data-bearing storage is listed first and marked in orange; each lane shows six and links to the rest.
View Apps
Online
The domain is in an enabled Nginx site from the latest completed scan and returned an HTTPS response below 500. For a sign-in challenge (401/403), which nginx can answer by itself, the app's upstream port must also accept a connection.
Unavailable
An enabled inventory domain that failed its live HTTPS check, returned a 5xx response, or showed only a login page while nothing listened behind it. Listed under the cards with the reason; health is cached for five minutes.
Categories
DEL supplies an initial category. Customize it per card; your override is saved only in this browser.
My order
Open Customize, drag cards, then choose My order. Stars, hidden cards, card size, spacing, and view mode are also browser-local.
Owner apps & sharing
Owner app(s)
App(s) DEL attributes this resource to. unassigned = no association rows (no owner chips). Orphans is different: no probable (≥60) owner — a resource can still have possible/weak claims and appear there.
Shared
Used by more than one app, or a system path such as /var/run/docker.sock or /etc. Removing one app never deletes a shared resource.
Containers — State / health
State
Docker runtime: running, exited, paused, restarting, …
Health
Docker healthcheck when defined: healthy / unhealthy / starting. no healthcheck means none configured — not a failure.
Images
Dangling
Untagged <none>:<none> leftover after rebuild — often reclaimable if unused.
Used by
How many containers reference this image.
Volumes
Orphan (resources tab)
No container currently mounts this volume.
Shared
Associated with more than one app.
Networks
Shared
Used across apps/projects. Built-ins (bridge/host/none) are never removed.
Attached
Containers currently on this network.
Directories & git
Dirty
dirty = uncommitted git changes; clean = clean tree; — = not a repo / unknown.
Size
Approximate on-disk size (du).
Nginx sites
not enabled
Config exists but is not in sites-enabled — not serving.
ssl
Config references a TLS certificate.
Orphans page
Unassociated
In the latest completed scan, no app owns the resource: there is no non-excluded association at confidence ≥60 (probable or stronger), and no protected app claims it. It can still carry weak (<60) or excluded claims — those show as owner chips elsewhere but do not count here.
Actionable
Default view. Real review candidates: custom systemd units, unused volumes, dangling/unused images, enabled named Nginx sites with no app (proxied or static/redirect-only), project dirs/git/.env with no owner, listeners tied to untracked app units.
System
OS/vendor noise — not abandoned apps. Examples: NetworkManager, sshd:22, Samba, distro cron/timers, Docker built-in networks, catch-all Nginx vhosts with no server_name, listeners of package-managed units. Hidden unless you choose “Show system & expected too”.
Expected
Situations that look unassociated but are intentional: parked (disabled) nginx configs; images still declared by a compose project that isn’t running; backup copies inside DEL’s backups directory (restore material, never planned for removal); the second socket of a dual-stack listener; a Git repo inside a directory row that is already listed.
Why listed
Per-row explanation of the classification. This page is review-only — it has no delete. Removal still goes through an app plan.
Jobs
dry run
Simulates every step; changes nothing on the host.
LIVE
Executes real helper operations (with safety gates). Striped like hazard tape wherever it appears.
success / failed / refused
Terminal outcomes. refused = a gate blocked the run.
Tables
Filter
The search box matches any column. Shortcut: /. Chips above a table toggle common values such as a status.
Column filter
The funnel beside a header: tick values from a list, or use operators (contains, equals, greater than, is empty, …). Clear filters resets them all.
Sort, columns, width
Click a header to sort; drag its right edge to resize. Columns shows or hides columns and switches compact rows. Each table remembers this in your browser.
Rows and export
Click a row to open what it names. CSV exports every filtered row, not just this page.
Assistant
Read-only
The assistant has no tools and cannot change anything. Removal still goes through an app's plan/confirm flow.
Scope
What the model is told about: the whole server, one application, the orphan list, one resource type, or a single resource.
Context truncated
The inventory facts were cut to the configured budget; the answer may miss items. Narrow the scope for full coverage.
Privacy
Inventory metadata (names, paths, tags, ports, evidence) is sent to Ollama Cloud. File contents, env values and secrets never are.
Times

Eastern (New York), compact MM-DD-YY H:MM AM/PM (e.g. 05-13-26 7:31 AM).
